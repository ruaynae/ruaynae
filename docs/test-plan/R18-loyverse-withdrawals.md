# R18 · เบิกวัสดุจากร้าน (Loyverse) เข้าต้นทุนโครงการ + สต็อกใกล้หมด + รายงานการเบิก — แผนและตารางตรวจรับ

> คำขอเจ้าของ 18 ต.ค. 2569:
> *"ช่างจะไปเบิกสินค้าจากที่ร้านมาใช้ในงานต่าง ๆ จะได้นำมาคิดเป็นต้นทุน … ลูกค้าทั่วไปที่มาซื้อหน้าร้านก็จะได้ราคาขายปลีก"*
> *"อยากให้ช่างคีย์เบิกของไป แล้วให้มันเด้งที่เครื่อง pos ด้วย … และให้ทำระบบสต็อกด้วย โดยถ้าสินค้าเหลือน้อย ให้แจ้งเตือนด้วย"*
> *"อนุมัติอัตโนมัติ แต่อยากมีหน้าตารางรายงานให้ผมดูย้อนหลังหน่อย จะได้ดูว่าเบิกไปเกินไหม"*

**สถานะ:** `☐` ยังไม่ตรวจ · `✅` ผ่านโดยมีหลักฐาน · `❌` ตก · `👤` ต้องคนตรวจ · `⚠️` ติดเงื่อนไข

## คำตอบเจ้าของ (ล็อกแล้ว)

| เรื่อง | คำตอบ |
|---|---|
| ระบบหน้าร้าน | **Loyverse POS** ที่ใช้อยู่ (ร้าน "เรือนแก้วเฟอร์นิเจอร์" · สินค้า 125 รายการ) — **ไม่สร้าง POS/สต็อกเอง** |
| ใครคีย์ใบขอเบิก | **หัวหน้าโครงการคีย์แทนช่าง** ผ่านหน้าเว็บหรือ LINE bot (ช่างไม่มีบัญชี — §2) |
| อุปกรณ์หน้าร้าน | แท็บเล็ต + เครื่องสแกนบาร์โค้ด + เครื่องพิมพ์ใบเสร็จ (ของ Loyverse เดิม) |
| เก็บเงินตอนเบิก | **ไม่เก็บ** → แคชเชียร์จ่ายด้วยวิธีชำระเงิน **"เบิกใช้งาน"** ที่ตั้งเพิ่มใน Loyverse |
| อนุมัติ | **อัตโนมัติ** — บิลเบิกเข้าเป็นรายจ่าย `approved` ทันที · จุดตรวจคือ**รายงานย้อนหลัง** |
| ราคาทุนที่ยังไม่มี (11 รายการเป็น 0) | **เติมทีหลังได้** ในหน้าของระบบเรา แล้วคิดต้นทุนย้อนหลังให้ |

## หลักคิด

- **Loyverse คือแหล่งความจริงของสต็อก** — สต็อกถูกตัดที่ Loyverse ตอนแคชเชียร์ออกบิลเท่านั้น ระบบเราอ่านอย่างเดียว
  (ไม่มีสต็อกสองชุดให้ drift)
- **ต้นทุนโครงการ = `line_items[].cost_total` ของบิล** (ทุน ณ ตอนขายที่ Loyverse จดไว้) **ไม่ใช่ราคาขาย**
  · ราคาบนบิลเบิกจะเป็นราคาปลีกก็ไม่กระทบต้นทุนโครงการ
- **บิลที่นับ = จ่ายด้วย "เบิกใช้งาน" เท่านั้น** · บิลขายลูกค้าทั่วไปไม่ถูกแตะ · `cancelled_at` มีค่า = ไม่นับ
  · `receipt_type = REFUND` + `refund_for` = คืนของ → ลดต้นทุนกลับ
- **ห้ามเชื่อเนื้อหา webhook** — webhook เป็นแค่สัญญาณ แล้วดึงบิล/สต็อกจาก API ด้วยโทเคนของเราเอง
  (ยังไม่รู้ว่า Loyverse มีลายเซ็นให้ตรวจไหม → URL มีรหัสลับในเส้นทางแบบเดียวกับ `/api/mcp/[key]`)
- **กันซ้ำด้วย `receipt_number`** (unique) — webhook ยิงซ้ำ / ดึงรอบซ้ำ = ไม่เกิดรายจ่ายสองใบ
- **ทุน 0 ≠ ทุนศูนย์บาท** — บรรทัดที่ Loyverse ให้ `cost = 0` เก็บเป็น `null` (= รอเติมทุน) ไม่ใช่ 0
  · เติมทุนแล้ว คิดต้นทุนบรรทัดที่ค้างย้อนหลัง · บรรทัดที่มีทุนอยู่แล้วไม่ถูกแก้ย้อนหลัง (snapshot เหมือน `wage_snapshot`)
- **โทเคน Loyverse อยู่ใน Supabase Vault** ไม่ใช่ env ของ Vercel (เหมือนคีย์ LINE — R16) · หน้าจอโชว์แค่ 4 ตัวท้าย

## ลำดับงานหน้างาน

```
หัวหน้าโครงการ (เว็บ / LINE)          แคชเชียร์ (แท็บเล็ตหน้าร้าน)              ระบบเรา
──────────────────────────────         ──────────────────────────────           ─────────────────────────────
คีย์ใบขอเบิก RQ-0012                 → เห็นในหน้า "ใบขอเบิกรอจ่าย"
 · โครงการ · ชื่อช่าง                    (เปิดคู่กับแอป Loyverse)
 · สินค้า × จำนวน (จากรายการ Loyverse)
                                          ช่างมาถึง → ออกบิลใน Loyverse
                                          · หมายเหตุบิล = RQ-0012
                                          · จ่ายด้วย "เบิกใช้งาน"            → webhook / รอบดึง → ดึงบิลจาก API
                                          · สต็อกตัดที่ Loyverse                 → จับคู่ RQ-0012 จากหมายเหตุ
                                                                                  → รายจ่ายหมวด "วัสดุจากร้าน"
                                                                                    ของโครงการนั้น · approved
                                                                                  → ใบขอเบิกเป็น "จ่ายแล้ว"
```

- บิล "เบิกใช้งาน" ที่**ไม่มีเลข RQ** หรือเลขไม่ตรง → เข้าคิว **"บิลเบิกที่ยังไม่ผูกโครงการ"** ให้เจ้าของเลือกโครงการเอง
  (ไม่ทิ้ง ไม่เดา)
- ใบขอเบิกที่ค้างเกิน 7 วันไม่มีบิลมาจับคู่ → ป้ายเตือน (หัวหน้ายกเลิกเองได้)

## ข้อมูล (ร่าง — ยืนยันกับเอกสาร API ก่อนเขียน migration)

| ตาราง | สาระ | RLS |
|---|---|---|
| `pos_items` | สำเนารายการสินค้าจาก Loyverse: `variant_id` (pk), `item_id`, `sku`, `name`, `category`, `pos_cost`, `price`, `in_stock`, `track_stock`, `synced_at` · **`cost_override`** (ทุนที่เจ้าของเติมเอง) · **`reorder_point`** (จุดเตือนของเรา) | อ่าน: เจ้าของ + หัวหน้าโครงการ (ไม่เห็นทุน — ผ่าน view) · เขียน: ระบบ + เจ้าของ (override/reorder) |
| `material_requests` | ใบขอเบิก: `request_no` (RQ-xxxx), `site_id`, `employee_id` (ช่าง · ไม่บังคับ), `requested_by`, `status` (`open`/`fulfilled`/`cancelled`), `note`, `via_line` | หัวหน้า: สร้าง/ยกเลิกของตัวเองในโครงการที่ดูแล · เจ้าของ: ทั้งหมด · แคชเชียร์: อ่านใบ `open` |
| `material_request_lines` | `variant_id`, `qty` | ตามใบ |
| `pos_receipts` | บิลจาก Loyverse: `receipt_number` (**unique**), `receipt_type`, `refund_for`, `receipt_date`, `cancelled_at`, `request_id`, `site_id`, `txn_id`, `raw` jsonb | **เจ้าของเท่านั้น** |
| `pos_receipt_lines` | `variant_id`, `qty`, **`unit_cost`** (null = รอเติมทุน), `cost_total` | **เจ้าของเท่านั้น** |

- รายจ่ายที่เกิด = `transactions` เดิม · หมวดใหม่ **"วัสดุจากร้าน"** (`is_material = true`) · `status = approved`
  · คอลัมน์ใหม่ `pos_receipt_id` ล็อกไม่ให้แก้ (เหมือน `keep_mcp_key` — §17 ข้อ 20) · ป้าย "จากร้าน (Loyverse)" ใน `/ledger`
  · 🔴 ยอดรายจ่าย = Σ `cost_total` ของบรรทัดที่มีทุน **คำนวณในฐานข้อมูล** · เติมทุนทีหลัง → trigger คิดยอดใบเดิมใหม่
  (audit_log เก็บ before/after ครบ)
- **ยอดเงินของร้านเป็นความลับจากหัวหน้าโครงการ** — หน้าใบขอเบิกของหัวหน้าเห็นชื่อสินค้า/จำนวน/คงเหลือ **ไม่เห็นทุน**
- **บทบาทแคชเชียร์:** ⚠️ ยังไม่ตัดสินใจ — ทางเลือก (ก) role ใหม่ `cashier` ล็อกอินด้วย PIN เห็นแค่หน้าใบขอเบิกรอจ่าย
  (ข) ใช้บัญชีเจ้าของบนแท็บเล็ตร้าน (ไม่แนะนำ — เห็นทุกตัวเลข) · ต้องถามเจ้าของ

## สต็อกใกล้หมด

- ตัวจุดเตือน = `pos_items.reorder_point` ของเรา (Loyverse `Low stock` ตอนนี้เป็น 0 ทุกรายการ) · ว่าง = ไม่เตือน
- ตัวกระตุ้น = webhook `inventory_levels.update` (ยืนยันแล้วว่ามีชนิดนี้) + ดึงซ้ำรอบเช้าเผื่อ webhook หาย
- ส่งเข้า LINE **รวบเป็นข้อความเดียวต่อรอบ** (โควตาฟรี 300/เดือน — R16) · สินค้าที่เคยเตือนแล้วไม่เตือนซ้ำจนกว่าจะเติมกลับเหนือจุด
- ในเว็บ: ป้ายตัวเลขบนเมนู + แท็บ "สินค้าใกล้หมด" · สต็อกติดลบ (ตอนนี้ 40 รายการ) แสดงแยกว่า "ยอดในระบบไม่ตรงของจริง"

## รายงานการเบิก (`/reports?tab=materials` · เจ้าของ)

ตอบคำถาม **"เบิกไปเกินไหม"** สามมุม:
1. **จ่ายจริงเกินใบขอเบิก** — ต่อบรรทัด: ขอ × จ่ายจริง × ส่วนต่าง · แถวที่จ่ายเกินขอ = สีส้ม · บิลไม่มีใบขอ = สีแดง
2. **ต่อโครงการ** — ต้นทุนวัสดุจากร้านสะสมรายเดือน · เทียบค่างาน (`contract_amount`) เป็น % · โครงการที่มีบรรทัดรอเติมทุน = ป้าย "ต้นทุนยังไม่ครบ"
3. **ต่อสินค้า / ต่อหัวหน้าโครงการ** — ใครเบิกอะไรไปเท่าไหร่ในช่วงวันที่เลือก
- ตัวกรอง: ช่วงวัน (`date-range.ts` ตัวเดิม) · โครงการ · หัวหน้าโครงการ · สินค้า/หมวด
- รวมยอดใน RPC `report_materials_*` (§7 — ห้ามดึงแถวมานับใน JS) · ทุกตาราง `.order()` + `.range()`
- เฟสหลัง: งบวัสดุต่อโครงการ + เตือนเมื่อเกินงบ (ตรงกับ "งบประมาณต่อโครงการ" ใน §14 เฟสหลัง)

## ยังไม่รู้ (ต้องได้จากเอกสาร Loyverse ก่อนเขียน M2/M4)

1. รายการชนิด webhook ทั้งหมด (มีบิลใหม่/แก้บิลไหม) และ**วิธียืนยันว่าคำเรียกมาจาก Loyverse** (ลายเซ็น/secret)
2. เนื้อหาที่ webhook ส่งมา — ครบหรือแค่สัญญาณ
3. ขีดจำกัดการเรียก API · การแบ่งหน้า (cursor)
4. `Create a receipt` ยอมให้กำหนดราคาต่อบรรทัดไหม — **ไม่บังคับ** (แผนนี้ไม่ต้องสร้างบิลเอง) เก็บไว้ยกระดับทีหลัง
5. `cost` ในบิลคือทุนเฉลี่ยหรือทุนที่ตั้งไว้ เมื่อเปิดส่วนเสริมสต็อกขั้นสูง
