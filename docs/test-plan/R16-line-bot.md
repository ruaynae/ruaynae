# R16 · สั่งงานผ่าน LINE bot — ตารางตรวจรับ

> คำขอเจ้าของ 29 ก.ย. 2569: *"อยากให้มันใช้กับไลน์ Bot ได้ด้วยครับ … พิมสั่งบอท เมนูที่ผมใช้ทุกวัน
> ที่ต้องเข้ามาเช็คหน้าเว็บ คือ 1. คีย์ค่าใช้จ่ายรายวัน 2. ตรวจเช็ครายชื่อคนเข้างาน แต่ละที่
> ที่หัวหน้างานคีย์มา 3. ตรวจสอบยอดที่หัวหน้างานตั้งเบิกให้ลูกน้องมา 4. คีย์ให้เบี้ยเลี้ยง ต่างจังหวัด"*
>
> แบบอ้างอิง: LINE bot ของ `C:\projects\huay` (webhook · ผูกบัญชีด้วยรหัส 6 หลัก · สถานะแชท ·
> rich menu · โหมดปลอม) — ยกโครงมา ไม่ยกโค้ดทั้งก้อน เพราะสิทธิ์และตารางต่างกัน

**สถานะ:** `☐` ยังไม่ตรวจ · `✅` ผ่านโดยมีหลักฐาน · `❌` ตก · `👤` ต้องคนตรวจ · `⚠️` ติดเงื่อนไข

## หลักการ

- **บอทคือหน้าจออีกแบบ ไม่ใช่กฎชุดใหม่** — ทุกการเขียนเรียกฟังก์ชัน/กติกาตัวเดียวกับเว็บ
  สวมสิทธิ์เจ้าของที่ผูกไว้ (แบบ `mcp_assume_owner` / `_bot_as` ของ huay) guard trigger ทุกตัวยังบังคับครบ
- **ทุกการเขียนเงินต้องผ่านการ์ดสรุป + ปุ่มยืนยัน** — รายการของเจ้าของเป็น `approved` ทันที ไม่มีคิวรับต่อ (บทเรียน R6)
- **แหล่งที่มาต้องแยกได้** — แถวที่มาจาก LINE ติดป้าย "บันทึกผ่าน LINE" ในแอปและ `/audit`
  ไม่งั้นประวัติอ่านว่าเจ้าของกดในเว็บทุกแถว (§17 ข้อ 20)
- **reply ก่อน push** — ตอบกลับทุกเมนูด้วย reply token (ฟรี) · push ใช้เฉพาะแจ้งเตือน (ข้อ 6)
- **ไม่ส่งยอดค่าแรงรายคนลงแชท** นอกจากคิวอนุมัติเบิกที่ต้องใช้ตัดสินใจ — แชทถูกส่งต่อได้
- **"วันนี้" = เวลาไทยเสมอ** (`todayInBangkok()`)
