# R23 · ลงชื่อคนเข้าโครงการย้อนหลังต้องให้เจ้าของอนุมัติ — ตารางตรวจรับ

> คำสั่งเจ้าของ 24 ต.ค. 2569: *"แก้ ไม่ให้หัวหน้างาน ลงค่าแรงย้อนหลังได้ ถ้าจะลงย้อนหลัง ต้องส่งให้ผมอนุมัติก่อน"*
>
> ตีความ: **ย้อนหลัง = `work_date` ก่อนวันนี้ตามเวลาไทย** (เมื่อวานก็นับ) · ครอบคลุม **ลง · แก้ · ลบ**
> แถว `attendance` ทั้งหมดของหัวหน้าโครงการ · เจ้าของไม่ถูกจำกัด · MCP/LINE สวมสิทธิ์เจ้าของจึงไม่ถูกจำกัด

**สถานะ:** `☐` ยังไม่ตรวจ · `✅` ผ่านโดยมีหลักฐาน · `❌` ตก · `👤` ต้องคนตรวจ

> 👤 ทุกแถวรอบนี้: เครื่องที่เขียนโค้ดไม่มี `.env.local` และรัน `tsc`/`next build` ไม่ได้ —
> ต้อง apply migration `20261024090000_attendance_backdate_approval.sql` (ไฟล์เดียว) แล้วรัน
> `node scripts/verify-backdate-db.mjs` (rollback ทั้งก้อน รันบนฐานจริงได้) จึงเปลี่ยนแถว BD-DB เป็น ✅

## 0 · ออกแบบ

| เรื่อง | ตัดสินใจ |
|---|---|
| ด่านจริง | trigger `guard_attendance_backdate` (before insert/update/delete บน `attendance`) — route แค่ตอบเร็ว |
| ผ่านด่าน | `auth.uid() is null` (สคริปต์/service) หรือ `is_owner()` |
| ทางอนุมัติ | ตาราง `attendance_backdate_requests` · เขียนผ่าน RPC `attendance_backdate_request/decide/cancel` เท่านั้น (ไม่มี policy เขียน) |
| อนุมัติแล้วเกิดอะไร | RPC insert `attendance` ในนามเจ้าของ → guard เดิมครบ (เพดาน 1 วันต่อคน · ปิดรอบจ่ายแล้วห้าม) · `created_by` = เจ้าของ ผู้ยื่นอยู่ในแถวคำขอ + audit |
| ต้นทุน | ยังไม่เกิดจนกว่าอนุมัติ (คำขอไม่ใช่ `attendance`) — ไม่มีความเสี่ยงบวกซ้ำแบบ §17 ข้อ 29 |
| เอาคนออกจากวันย้อนหลัง | หัวหน้าทำไม่ได้ (ปุ่มซ่อน + trigger) — ให้เจ้าของลบเอง · ยังไม่มีคำขอ "ลบ" |
| แจ้งเตือน | enum ใหม่ `backdate_pending/approved/rejected` · ป้ายเมนู "รออนุมัติ" รวมคำขอนี้ · LINE push ยัง **ไม่** ครอบคลุมคำขอนี้ (ดู §ที่ยังไม่ทำ) |

## 4 · ที่ยังไม่ทำ (บอกตรง ๆ)

- ผู้ยื่นไม่ได้รับ LINE push (กระดิ่ง/แอปเท่านั้น) · เจ้าของก็ไม่ได้ LINE push สำหรับคำขอนี้ — `LINE_PUSH_KINDS` มีแค่ `txn_pending`/`advance_pending` และเมนูอนุมัติในบอทยังไม่รู้จักคำขอชนิดนี้
- หัวหน้าขอ "ลบ/แก้" แถวย้อนหลังไม่ได้ (ต้องให้เจ้าของทำเอง)
